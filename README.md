# Монитор электропитания для Home Assistant OS

Интеграция приблизительно учитывает время, когда Home Assistant на мини-ПК не проявлял активности. Она записывает heartbeat каждые 5 минут и считает отключением разрыв между записями **от 10 минут включительно**. После возобновления работы появляется запись о простое и, если настроен Telegram, отправляется сообщение.

## Установка

1. Сделайте резервную копию Home Assistant.
2. Распакуйте ZIP в каталог конфигурации Home Assistant (`/config`). Должен получиться путь `/config/custom_components/power_activity_monitor/manifest.json`. Содержимое ZIP включает папку `custom_components` целиком.
3. Перезапустите Home Assistant.
4. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Монитор электропитания**.
5. При желании выберите сущность `notify.*` вашего Telegram Bot и время отчёта. Эти параметры можно изменить позже через **Настроить** у интеграции. Время берётся из часового пояса Home Assistant.

Интеграция создаёт отдельное устройство «Монитор электропитания» и семь сенсоров: простой за текущую неделю, месяц, год и всё время (часы, `device_class: duration`), последняя активность (`timestamp`), последний простой (часы, `duration`), количество отключений. Отчёт приходит по понедельникам в выбранное время за предыдущую календарную неделю. Если Home Assistant тогда был выключен, отчёт уйдёт после следующего запуска или heartbeat; повторная отправка после успешной записи состояния не планируется.

### Telegram

Сначала настройте штатную интеграцию [Telegram Bot](https://www.home-assistant.io/integrations/telegram_bot/) и разрешите нужный chat ID. Она создаёт отдельную сущность `notify.*` для чата. Проверить её можно действием `notify.send_message` в инструментах разработчика. Затем выберите эту сущность в настройках монитора. Если отправка не удалась, монитор попробует ещё раз на следующем heartbeat. Если `notify.*` не выбран, монитор всё равно считает простои; ожидающие сообщения будут отправлены при последующем выборе адресата.

## Как трактовать показания

- Это **оценка отсутствия активности HA**, а не показание электросчётчика. Сбой, зависание, обновление и ручное выключение мини-ПК выглядят как отключение питания.
- Начало простоя приблизительно: последняя запись heartbeat могла быть на 0–5 минут раньше фактического выключения. Конец — первый heartbeat после запуска. Интервалы короче 10 минут не учитываются. Если HA продолжал работать на ИБП, отключение электричества обнаружено не будет.
- Время по локальным календарным дням распределяется между неделями, месяцами и годами. Неделя начинается в понедельник, используется ISO-нумерация недель. Счётчик в отчёте относит событие к неделе его начала.
- Статистика хранится в `.storage/power_activity_monitor_<id>` и сохраняется на каждом heartbeat. Показатель «за всё время» означает время **с момента установки**. Старые события автоматически не импортируются. Состояние при кратком перезапуске сохраняется; при повреждении файла хранилища корректность старых данных не гарантируется.
- При аварийном выключении накопителя последняя запись может не сохраниться. Telegram может получить дубликат сообщения, если HA остановился после отправки, но до отметки об успешной отправке в хранилище.

## Переход со старых YAML-сенсоров

1. Запишите их показания, если нужен архив. Интеграция начинает отдельную историю с момента установки и не прибавляет старые числа.
2. Удалите из `configuration.yaml` старые `template`, `history_stats`, `utility_meter`, `counter` и автоматизации, которые **сами считают эти же отключения**. Не удаляйте другие записи из этих разделов.
3. Перезапустите HA, установите и добавьте эту интеграцию, как описано выше. Если старые автоматизации отправляли Telegram-уведомления о простое, отключите и их, чтобы не получать два сообщения об одном событии.
4. Обновите карточки, графики и автоматизации на новые сущности устройства. Имена сущностей могут получить суффикс, если старое имя занято; используйте фактические `entity_id` из интерфейса HA.

Не складывайте показания старых и новых сенсоров без отдельной сверки периодов: интервал при переходе может быть учтён дважды.
